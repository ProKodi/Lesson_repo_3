# Разминка 
## Какова основная цель тестирования ПО?
1) Выявить ошибки и дефекты, 
2) Проверка на то что код корректен / соответствует требованиям 

## Почему «исчерпывающее тестирование» невозможно?
Невозможно, потому что количество возможных входных данных, сценариев работы и состояний программы может быть практически бесконечным.   
Проверка всех возможных вариантов потребовала бы слишком много времени и ресурсов.

## Чем позитивное тестирование отличается от негативного?
`Позитивное тестирование` проверяет работу программы на корректных и допустимых данных.  
`Негативное тестирование` проверяет реакцию программы на некорректные, недопустимые или неожиданные данные.

Пример: поле «Возраст»:
* `Позитивное` — ввод 25 → система принимает значение.
* `Негативное` — ввод abc или -5 → система корректно сообщает об ошибке.

## Что такое «дефект» (баг)? Дайте определение своими словами.
Ошибка, из-за которой ПО работает не так, как было задумано

## Назовите этап жизненного цикла тестирования, на котором определяют, когда можно начинать тестирование.
Это этап планирования тестирования. 
На нём определяют:
1) когда начинать тестирование, 
2) какие условия должны быть выполнены 
3) какие ресурсы потребуются.


## Какие бывают этапы жизненного цикла, почему именно этот этап?
Основные этапы **жизненного цикла тестирования ПО (STLC)**:

1. **Анализ требований** — определяют, что именно нужно тестировать.
2. **Планирование тестирования** — определяют цели, объём, сроки, ресурсы и условия начала/окончания тестирования.
3. **Разработка тестов** — создают тест-кейсы и сценарии.
4. **Подготовка тестовой среды** — настраивают необходимое оборудование и ПО.
5. **Выполнение тестов** — проводят тестирование и фиксируют дефекты.
6. **Завершение тестирования** — анализируют результаты и подводят итоги.


## Что такое «толерантность к ошибкам»?
Способность программы **продолжать работать правильно или приемлемо даже при возникновении ошибок, сбоев или некорректных данных**.

# Для решения задачи:
## Типы
| Понятие                          | Что это                                                               |
| -------------------------------- | --------------------------------------------------------------------- |
| **Ошибка (Error)**               | Неправильное действие или решение **человека** при разработке         |
| **Дефект (Defect)**              | Недостаток, **заложенный в программном продукте** вследствие ошибки   |
| **Слабое место (Vulnerability)** | Уязвимость, которую можно использовать для нарушения **безопасности** |
| **Сбой (Failure)**               | Неправильное поведение системы, **наблюдаемое при выполнении**        |

Главное различие:
**Ошибка → создаёт дефект → дефект может вызвать сбой.**  
**Слабое место** — отдельное понятие, связанное именно с **безопасностью**. Оно может быть разновидностью дефекта, создающей возможность атаки.

## Группы ошибок
Если речь о **группах ошибок в тестировании ПО**, обычно выделяют:
1. **Ошибки требований** — требования сформулированы неправильно или неполно.

2. **Ошибки проектирования** — неправильно спроектирована структура или логика системы.

3. **Ошибки реализации (кодирования)** — разработчик неправильно реализовал требования.

4. **Ошибки интерфейса** — проблемы с отображением или взаимодействием пользователя с системой.

5. **Ошибки данных** — некорректная обработка, хранение или преобразование данных.

6. **Ошибки интеграции** — неправильное взаимодействие между компонентами или системами.

7. **Ошибки окружения/конфигурации** — проблема возникает из-за настроек ОС, сервера, БД, сети и т. д.

Коротко:
```
Требования → Проектирование → Код → Интерфейс → Данные → Интеграция → Окружение.
```

## Жизненный цикл разработки ПО
1. **Анализ требований** — определяют, что должна делать система.

2. **Проектирование** — разрабатывают архитектуру, структуру и интерфейс.

3. **Разработка (кодирование)** — программисты создают программный продукт.

4. **Тестирование** — проверяют работу программы и выявляют дефекты.

5. **Внедрение** — устанавливают ПО и вводят его в эксплуатацию.

6. **Сопровождение** — исправляют ошибки, обновляют и улучшают систему.

**Кратко:**
```
Требования → Проектирование → Разработка → Тестирование → Внедрение → Сопровождение
```
